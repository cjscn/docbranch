# docbranch 文档递归批注工具｜产品需求文档（PRD）

## 1 项目概述

### 1.1 项目名称

文档递归批注工具（静态网页版）

### 1.2 项目背景

在编写技术规则、产品文档（如号码筛选规则文档）过程中，存在以下痛点：

1. 文档内专业名词、关键语句需要附加解释说明，**不希望注释嵌入原文污染文档本体**；
2. 注释内部依然包含专业术语，需要**对批注说明内的词语继续追加解释（递归 / 多层级标注）**；
3. 传统批注工具，在文档前文增删内容后，批注锚点位置错位失效；
4. 需要保留完整批注历史，支持版本回溯，可随文档一同纳入 Git 版本管理；
5. 期望可视化直观展示「原文片段 ↔ 批注说明」之间的关联关系。

### 1.3 项目目标

实现**左右双栏布局**的纯前端静态网页批注工具，可部署至 GitHub Pages 公网访问。

**一期目标（当前实现范围）：**

- 左栏：Monaco Editor Markdown 文档编辑区，被标注文字高亮显示；
- 右栏：树形展示批注卡片，支持无限层级递归子批注；
- 交互：右键菜单触发批注添加，子批注同样右键菜单触发；
- 持久化：localStorage 自动保存 + 手动导入/导出 JSON；
- 核心能力：**批注卡片内的关键词同样支持新增子批注**，实现多层递归解释；
- 边界处理：原文删除 → 批注灰显失效；原文修改 → 提示变更。

**二期预留（不在本期实现）：**

- SVG 红色虚线指引连线
- GitHub API 一键提交回仓库
- 拖拽分割线、批注编辑、标签系统

## 2 整体页面布局

页面采用左右分栏布局，全屏高度：

| 区域 | 占比 | 功能说明 |
| --- | --- | --- |
| 左栏【原文档区】 | 60% | Monaco Editor 编辑器，展示 / 编辑 Markdown 文档；带批注的文本高亮显示 |
| 右栏【标注说明区】 | 40% | 树形展示所有批注卡片，主批注、子批注分层缩进展示；卡片内选中文字支持右键创建子批注 |

> 两栏之间为固定分割线（一期暂不支持拖拽调整，二期实现）。

## 3 功能需求

### 3.1 原文档编辑模块（左侧）

1. 基于 **Monaco Editor**（CDN 引入，VS Code 同款编辑器），支持 Markdown 语法高亮、撤销 / 重做、多光标；
2. 文档前文增删内容时，所有批注锚点（Range）由 Monaco 自动跟随，**位置不会错位**（Monaco 内置能力）；
3. 右键菜单扩展：
   - 在选中的文字上右键 → 菜单显示「添加批注」→ 弹出输入框 → 输入说明后保存；
   - 未选中文字时右键，不显示「添加批注」菜单项；
4. 高亮样式：被标注文本使用 **`#4a7aff` 蓝紫色背景 + 深色半透明 `rgba(74,122,255,0.25)`** 作为高亮标记（适配深色主题，对比度充足）；
5. 只读 / 编辑模式切换：顶部工具栏提供开关，防止误改文档；
6. 点击左侧高亮文本 → 右侧面板自动滚动定位到对应批注卡片并高亮激活。

### 3.2 批注管理模块（右侧，支持递归子批注）

#### 3.2.1 批注卡片

每条批注以独立卡片形式展示，包含以下元素：

| 元素 | 说明 |
| --- | --- |
| 🔼 原文片段 | 被标注的文字，淡蓝色高亮展示（Markdown 纯文本显示） |
| 📝 批注说明 | 支持 Markdown 渲染（**加粗**、列表、`代码块`、> 引用），使用 marked.js 解析 |
| ⚠️ 变更提示 | 当 sourceText 与当前 Range 实际文本不一致时，显示黄色警告图标 |
| 🔗 定位按钮 | 点击后左栏自动滚动并聚焦到对应的原文位置（或父卡片内位置） |
| 🗑️ 删除按钮 | 点击删除该批注及其全部子批注（含确认弹窗） |

#### 3.2.2 层级结构

支持无限层级树形批注：

- **一级批注**：来源 = 左侧 Monaco Editor 选中的文本
- **子批注**：来源 = 右侧批注卡片内选中的文字，缩进展示（左侧 `border-left: 2px solid #4a7aff` 视觉区分层级）
- 子批注支持继续创建下一级子批注，无深度限制

#### 3.2.3 子批注交互

在右侧批注卡片内选中文字 → 右键 → 菜单显示「添加子批注」→ 弹出输入框 → 保存后生成缩进的子卡片。子批注卡片内的选中文字同样高亮（使用与一级批注相同的 `#4a7aff` 高亮样式）。

#### 3.2.4 批注列表顶部工具条

右栏顶部提供以下工具：

| 功能 | 说明 |
| --- | --- |
| 🔍 搜索框 | 输入关键词，过滤 sourceText 或 note 匹配的批注，实时生效 |
| 👁️ 高亮开关 | 一键隐藏 / 显示左栏所有批注高亮（专注阅读模式） |
| 📊 统计面板 | 显示批注总数、一级批注明细、子批注层级分布 |

#### 3.2.5 单条批注操作

- **定位原文**：点击 🔗 按钮，左栏滚动并聚焦到对应位置
- **删除批注**：点击 🗑️ 按钮 → 弹出确认框 → 确认后删除该批注及其全部子批注（级联删除）
- **确认更新**（仅 stale 状态批注）：sourceText 不匹配时，点击 ⚠️ 旁的「确认更新」按钮，将 sourceText 更新为当前 Range 的实际文本

### 3.3 边界情况处理策略

#### 3.3.1 原文片段被用户删除（orphaned 状态）

- **判定**：Monaco Range 指向的行号超出文档范围，或 Range 为空（开始/结束位置相同且该位置无字符）
- **表现**：
  - 批注卡片标记为 **orphaned**，整体灰显（opacity 0.5）
  - 卡片顶部显示标签「⚠️ 原文已删除」
  - 卡片仍保留在右栏树中，不自动删除
- **用户操作**：点击 🗑️ 手动删除

#### 3.3.2 原文片段被用户修改（stale 状态）

- **判定**：Monaco Range 仍然有效（位置未丢失），但该范围内的实际文本与保存的 `sourceText` 不一致
- **表现**：
  - Monaco Range 自动跟随，**位置仍然准确**（Monaco 内置能力），左栏高亮仍在正确位置
  - 批注卡片标记为 **stale**，显示黄色 ⚠️ 图标
  - hover ⚠️ 显示 tooltip：「原文本：`xxx` → 当前文本：`yyy`」
  - 卡片内原文片段区域使用黄色背景标记（区别于正常的淡蓝色）
- **用户操作**：
  - 可忽略（认为修改后的文本仍然是同一个标注对象）
  - 可点击「确认更新」按钮，将 sourceText 更新为当前实际文本
  - 可直接删除该批注

#### 3.3.3 文档整体替换 / 大幅重排

- 可能导致大量 Range 失效（orphaned）或 sourceText 不匹配（stale）
- 表现：右栏会出现大量灰显或黄色警告的卡片
- 建议用户：通过「导入 JSON」恢复上一次有效的批注数据，或手动清理失效批注

### 3.4 导入 / 导出与持久化

#### 3.4.1 localStorage 自动保存

- **触发时机**：文档内容变更后 500ms 防抖自动保存；批注增删改后立即保存
- **保存内容**：完整数据快照，包含 `docContent`（Markdown 原文）和 `annotations`（批注树）
- **key 命名**：`doc-branch-snapshot-v1`
- **启动恢复**：页面加载时自动读取 localStorage，恢复文档内容和批注高亮

#### 3.4.2 手动导出

- 顶部工具栏「导出 JSON」按钮
- 导出文件名：`annotations-tree.json`
- 导出内容：完整数据结构（见第 4 节）

#### 3.4.3 手动导入

- 顶部工具栏「导入 JSON」按钮 → 选择本地文件
- 导入时弹出选项：**合并**（保留现有批注 + 导入新批注）或 **覆盖**（完全替换）
- 导入后自动刷新左栏高亮和右栏卡片

### 3.5 快捷键

| 快捷键 | 功能 |
| --- | --- |
| `Ctrl/⌘ + S` | 手动触发保存（等同 localStorage 自动保存） |
| `Ctrl/⌘ + Shift + E` | 导出 JSON 文件 |
| `Ctrl/⌘ + Shift + I` | 导入 JSON 文件 |
| `Esc` | 关闭右键菜单、取消搜索过滤 |

### 3.6 核心交互流程

1. **添加一级批注**：左栏选中文字 → 右键 → 「添加批注」→ 弹窗输入说明 → 保存 → 原文高亮 + 右栏生成一级批注卡片
2. **点击高亮定位**：左栏点击高亮文字 → 右栏滚动定位到对应卡片并激活
3. **添加子批注**：右栏批注卡片内选中文字 → 右键 → 「添加子批注」→ 弹窗输入 → 保存 → 缩进生成子卡片，卡片内选中文字也高亮
4. **文档修改自动跟随**：左栏编辑文档 → Monaco 自动更新所有 Range → 左栏高亮位置实时刷新 → localStorage 自动保存
5. **原文删除灰显**：删除被标注的原文 → 对应批注卡片灰显，标记为 orphaned
6. **原文修改提示**：修改被标注的原文片段 → 对应批注卡片显示 ⚠️，sourceText 不匹配

## 4 数据结构设计

### 4.1 整体导出格式

```json
{
  "version": 1,
  "exportedAt": "2026-10-09T10:00:00Z",
  "docContent": "# 号码筛选规则\n\n不选任何条件 | 该维度不过滤，全部 80 个号码通过\n",
  "annotations": [...]
}
```

- `version`：数据格式版本号，用于未来版本迭代时的兼容性判断
- `exportedAt`：导出时间戳（仅导出时存在，localStorage 内保存时可为空）
- `docContent`：完整 Markdown 原文，保证导入时文档内容与批注锚点匹配
- `annotations`：批注树数组

### 4.2 批注节点结构

```json
{
  "id": "uuid-1",
  "parentId": null,
  "status": "active",
  "range": {
    "startLineNumber": 3,
    "startColumn": 30,
    "endLineNumber": 3,
    "endColumn": 40
  },
  "sourceText": "80个号码",
  "note": "表示当前筛选池中的全部候选号码。",
  "children": [
    {
      "id": "uuid-1-1",
      "parentId": "uuid-1",
      "status": "active",
      "noteOffsetStart": 12,
      "noteOffsetEnd": 16,
      "sourceText": "候选号码",
      "note": "指当前筛选规则下，尚未被任何条件排除的号码集合。",
      "children": []
    }
  ]
}
```

### 4.3 字段说明

#### 公共字段（一级批注 + 子批注共有）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 批注唯一标识 UUID |
| `parentId` | string / null | 父批注 ID，一级批注为 `null` |
| `status` | string | 批注状态：`active`（正常）/ `stale`（原文已变更）/ `orphaned`（原文已删除） |
| `sourceText` | string | 被标注的原文片段，用于文本校验 |
| `note` | string | 批注说明文字（支持 Markdown 语法，使用 marked.js 渲染） |
| `children` | array | 子批注数组，可无限嵌套 |

#### 一级批注独有字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `range` | object | Monaco Editor 行列定位信息，包含 `startLineNumber` / `startColumn` / `endLineNumber` / `endColumn`。Monaco 自动跟随文档变化，保证锚点位置不丢失 |

#### 子批注独有字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `noteOffsetStart` | number | 在父批注 `note` 文本中的**字符起始偏移量**（0-based） |
| `noteOffsetEnd` | number | 在父批注 `note` 文本中的**字符结束偏移量** |

> **为什么子批注不用 Monaco Range？**
> 子批注的 sourceText 来自右栏批注卡片内的 DOM 文本，不是 Monaco Editor 管理的内容，因此无法用行列号定位。使用**字符偏移量**是最简洁可靠的方案——父批注的 `note` 是纯字符串，偏移量天然稳定。

整体采用 **深色主题**，适配技术文档阅读：

### 5.2 高亮样式

| 状态 | 背景色 | 说明 |
| --- | --- | --- |
| 正常高亮（active） | `#4a7aff` 实色 + `rgba(74,122,255,0.25)` 半透明叠加 | 适配深色背景，对比度充足（WCAG AA） |
| 变更提示（stale） | `#e0af68` 黄色背景 + ⚠️ 图标 | 区别于正常高亮 |

### 5.3 工具栏图标

使用 emoji 或简洁 SVG 图标（🔍 搜索 / 👁️ 高亮开关 / 🔗 定位 / 🗑️ 删除 / ⚠️ 警告），避免引入图标库依赖。

### 5.4 二期预留

- 红色贝塞尔虚线指引连线：`stroke: #ff6b6b` + `stroke-dasharray: 6 4`，两端圆角，曲线向上拱起 20-30px
- SVG 悬浮顶层（pointer-events: none），不影响文字选中和鼠标点击

## 6 非功能需求

### 6.1 部署与访问

- **GitHub Pages 部署**：将 `index.html` 及所有依赖（CDN 引用的 Monaco Editor）推送至 GitHub 仓库，开启 Pages 服务即可公网访问
- **HTTPS 环境**：GitHub Pages 默认 HTTPS → Monaco Editor 的 Web Worker 加载无 CORS 问题
- **离线可用（降级方案）**：如果不部署 GitHub Pages，也可本地启动简单 HTTP 服务器（如 `python -m http.server`）访问。**注意：直接双击 `file://` 打开时，Monaco Worker 可能因 CORS 限制无法加载**（编辑功能降级为只读基础模式）

#### 双仓库部署架构（GitHub Free 账号推荐）

GitHub Free 账号的 Pages 只能从 Public 仓库构建，但文档/批注数据需要 Private。采用双仓库分离方案：

```
仓库 A（Public）: docbranch-host
└── index.html   ← 工具壳（零数据，手动上传一次）

仓库 B（Private）: docbranch-data
├── docs/*.md
├── annotations/*.annotations.json
└── docbranch-index.json
```

- 工具壳通过 GitHub Pages 托管公网访问（`https://用户名.github.io/docbranch-host/`）
- GitHub Sync 通过 PAT 单独读写 Private 仓库 B（用户在 ⚙️ 设置里配置仓库 B 的地址）
- 代码层面零改动：所有 `cfg.repo` 引用动态读取用户配置，无硬编码
- 安全：仓库 B 的内容只有用户本人 + PAT 持有者能访问

#### 三种部署方案对比

| 方案 | 账号类型 | 仓库数 | 优点 | 缺点 |
|------|---------|--------|------|------|
| GitHub Pro 单仓库 | Pro ($4/月) | 1 | 最干净 | 月费 |
| GitHub Free 双仓库 | Free | 2 | 免费 | 需记两个仓库名 |
| Cloudflare Pages | 免费 | 1 | Private 仓库直连 + 密码保护 + 国内快 | 需 Cloudflare 注册 |

### 6.2 持久化

- **一期**：localStorage 自动保存 + 手动导入 / 导出 JSON
- **二期预留**：GitHub REST API 一键 commit 回仓库（需要配置 Personal Access Token，安全性权衡后决定是否启用）

### 6.3 性能

- Monaco Editor 加载速度：首次加载 ~1-2s（CDN 缓存后 ~200ms）
- 批注卡片渲染：100 条批注以内，右栏树形渲染 < 50ms
- localStorage 读写：< 10ms（100KB 数据量）
- 防抖自动保存：500ms

### 6.4 兼容性

- Chrome 100+、Edge 100+（现代 Chromium 内核）
- macOS Safari 16+（基础功能）

## 9 示例场景（号码筛选规则文档）

> 原文片段：`不选任何条件 | 该维度不过滤，全部 80 个号码通过`

### 9.1 正常流程

1. 左栏选中 `80个号码` → 右键 → 「添加批注」→ 输入 `表示当前筛选池中的全部候选号码。` → 保存
2. 左栏该文本出现蓝紫色高亮，右栏生成第一张一级批注卡片
3. 在这张卡片的批注说明中，选中 `候选号码` → 右键 → 「添加子批注」→ 输入 `指当前筛选规则下，尚未被任何条件排除的号码集合。` → 保存
4. 右栏缩进生成子批注卡片，卡片内 `候选号码` 也高亮显示
5. 点击左栏 `80个号码` 高亮 → 右栏自动滚动定位到第一张卡片

### 9.2 边界场景

6. 用户删除原文中的 `全部 80 个号码通过` 这段文字 → 对应批注卡片灰显，顶部显示「⚠️ 原文已删除」
7. 用户将 `80个号码` 改为 `80个数字` → 对应批注卡片正常高亮位置不变（Monaco Range 跟随），但卡片内出现 ⚠️ 图标，hover 显示「原文本：80个号码 → 当前文本：80个数字」
8. 用户点击「确认更新」→ sourceText 同步为 `80个数字`，⚠️ 图标消失
